# 0.1.1-beta.13 — Compact operator workspaces and release management

Prompts, Script Library, New Task and Jobs open into compact working controls.
The drawer starts with navigation, uses smaller rows and selects client
inventory, management and settings precisely. Topbar and login branding remain.

## Operator workspaces

Prompts uses a left library beside the editor, a focused blank New draft,
visible Save/Cancel and secondary policy/audit details. Dirty drafts survive
failed saves; selection, tenant changes and navigation require a discard
decision. Guidance revisions, tenant defaults and archived history retain their
existing semantics.

Script Library keeps its short tree directly below the filters. New Script
supports root, existing-folder and validated nested-folder placement using the
existing logical library model and type catalogue. Creation expands and selects
the new path and focuses the editor. Stored types do not acquire execution
capabilities; creating library content does not run it.

New Task keeps scoped targets, the short expandable command editor, parameters
and launch status together. Target details show actual address and connection
data. Mode changes, Expand and Advanced retain draft values. Scope changes fence
old history reads and rotate generated launch IDs; explicit operator IDs remain
available. Queued/running/terminal feedback uses the existing scoped task APIs
with a result/history link, while approvals and duplicate guards remain.

Jobs starts in Definitions with page-scoped summaries and visible Run, Edit,
Clone and Delete actions. New/Edit uses neutral compact tabs and persistent
actions. Create and add steps persists one job ID and continues in the same
editor. Child edits retain unsaved definition, schedule and runtime settings;
partial clone failures reconcile the new identity before further edits. Run
keeps the confirmed parameter flow and retains its busy guard while a request
is pending.

## Local release lifecycle and Activity

The release eligibility summary requests a supported ten-item page and displays
a smaller sample. Upstream checks distinguish confirmed missing or changed
assets from unavailable checks while retaining usable verified local data.

Delete local release and files previews the selected version, runtimes, imports,
packages, reclaimable storage and blockers. Eligible local records and owned
files are purged through a durable recoverable journal. Enabled offers, active
imports/transfers/updates, rollout pins, install links, rollback dependencies and
shared or unsafe storage block cleanup. Retained update snapshots and the
deletion receipt remain distinct from live package records. Scheduled automation
cannot re-import a deleted version until an operator deliberately imports it.
Local cleanup does not delete upstream releases or installed client software.

Activity receives authenticated SSE invalidations for committed changes and
coalesces refreshes of the current filtered server page. Reconnect obtains a
fresh authoritative snapshot. Filters, pagination, group expansion and manual
Refresh remain available; Live/Reconnecting/Paused reflects the subscription
and snapshot state. Leaving the view, replacing scope or logging out disposes
the active subscription.

## Upgrade and acceptance

Apply the normal forward PostgreSQL migration. It adds durable cleanup receipts
and archive transfer leases, and separates retained historical attempts from
nullable live release references. Schema downgrade is blocked when historical
attempts reference purged packages; account for this guard in rollback planning.

The generic hosted workflows produce native client, CLI and MCP archives,
checksums, SBOMs, the digest-pinned Compose bundle, publication record and all
five established public images. Build/distribution integrity and owner deployed
functional acceptance are recorded separately. Owner deployed-beta acceptance
remains **pending retest** unless separately executed and recorded.
