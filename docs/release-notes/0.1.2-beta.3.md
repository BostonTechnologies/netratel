# NetRatel 0.1.2-beta.3

Addresses [credential access editing and creation follow-up #429](https://github.com/BostonTechnologies/netratel/issues/429).

## Credential access

The Details page passed the literal string `detail.Id` into the access editor's
string parameter. Its request-history GET therefore used an invalid credential
identifier and returned HTTP 400 with `review_credential_id_invalid`, which the
editor replaced with a generic loading error. The page now passes the selected
credential's actual ID. This binding affects both local and OIDC accounts.

Access loading, review and save failures now show the failing stage, HTTP status,
safe failure code and available correlation reference. Matching Web/API log
events contain safe diagnostic fields. Failed initialization still withholds the
editable snapshot until current grants, authority and any pending review have
loaded together; retries recover the same submitted review.

Credential creation follows **Connection → Server access → Tenant access →
Review & create**. Server and tenant permissions have separate selectors,
selection counts and labelled information popovers. Either individual scope may
be empty, with at least one permission required overall. Back/Next retains the
draft and successful creation retains the one-time secret acknowledgement.

See the updated [HTTP MCP setup guide](../mcp-http/setup.md).

## Verification scope

The rendered page regression reproduces the literal-ID request before the fix
and covers reopening credentials with small and multi-tenant grant sets. Focused
API tests exercise the actual invalid-ID response contract and local/OIDC
review/application without replacing the secret or exact expiry. Browser fixture
coverage checks the revised wizard in light/dark and narrow layouts.

These checks do not establish authenticated acceptance on an owner deployment.
Public distribution integrity and owner functional acceptance remain separate
states in the release publication record.
