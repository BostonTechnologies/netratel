# NetRatel 0.1.4-beta.4

Unrestricted HTTP MCP tenant policies now admit eligible existing and newly enrolled clients without a hidden target-profile prerequisite. This corrects the complete local-credential delegation and API route for stored monitoring reads, including offline clients. Existing integrations retain their credentials, grants, exact expiry and policies.

Missing profiles, validated profiles and corrupt persisted profiles have distinct semantics across dispatch, discovery and inspection. Explicit applicable Denies win; unresolved potentially applicable profile-dependent Denies fail closed with `target_profile_required`. Invalid profiles return `target_profile_invalid`, including under Development access. Tenant/resource/principal/operation/agent restrictions, parent-policy limits, owner authority, confirmations and revision checks remain effective.

The wizard reviews current/new client coverage, the complete operation list and exclusions, working directories, shells, output/concurrency limits, confirmations and active-tenant deletion. Server All access includes the supported policy administration operations. Creation remains atomic. Both the created credential view and existing Details provide reusable exact operation/tenant/client authorization checks and labelled representative samples. Authorization allowed and unchecked runtime readiness remain distinct; validation does not execute mutations.

AI Chat and AI Ops retain healthy receivers through long model silence. Supported admission and session/turn evidence permit the exact late answer and completion to persist once after unknown delivery. Existing text-admission attachment support remains intact. Disconnects, later/unrelated output, missing terminal correlation and uncertain historical recovery retain their limits; no message, tool, job or approval is automatically replayed.

Addresses [#477](https://github.com/BostonTechnologies/netratel/issues/477) and the receiver/late-result work related to [#474](https://github.com/BostonTechnologies/netratel/issues/474). Provider latency, malformed load-tool calls and the deferred durable daemon replay/ownership contract remain separately tracked in [#475](https://github.com/BostonTechnologies/netratel/issues/475).

Hosted build/publication integrity and deterministic regressions are separate from owner deployment acceptance. Upgrade all serving components from the digest-pinned bundle, keep the existing credential unchanged, check the exact monitoring operation in Details, and invoke actual reads for both selected tenants/current and new clients plus server scope. Run bounded command/file/job/policy actions only on authorized disposable targets with explicit confirmations. Retest a long quiet AI turn and reconnect; preserve the original stalled conversation and reconcile only from valid evidence. Production deployment acceptance remains pending owner retesting.
