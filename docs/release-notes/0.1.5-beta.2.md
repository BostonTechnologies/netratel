# NetRatel 0.1.5-beta.2

This prerelease delivers execution groups and multi-node jobs from [#696](https://github.com/BostonTechnologies/netratel/issues/696).

- Tenant-owned execution groups retain explicit stable client IDs, revisions and membership. Jobs select one group, explicit nodes, a bounded server filter or a declared typed runtime input. Preview resolves the whole authorized set before pagination.
- One agentless parent freezes its definition, complete target plan and execution settings. Durable slots reuse the existing single-agent native authority and receipts for each node's ordered workflow. Thread Count supports 1–100; both node-failure policies preserve running work, and uncertain physical execution closes new admission without replay.
- Typed Flow targeting supports the low-disk investigation through the trusted `alert.agentId`. Fresh admissions resolve current membership; continuation and original-execution reruns retain the admitted plan under current authority. Old fixed Flow hashes, singular Requests and narrowly proven legacy schedule events remain compatible.
- REST, CLI, stdio and HTTP MCP share whole-plan reviewed admission, per-agent grants, atomic quotas and protected recovery before parent creation. Node/step-run identities and bounded forward cursors keep concurrent output isolated.
- Tenant and job editors have full responsive sections, persistent member selection and explicit group saves. Run details show hostname panels, nested steps, selected-node follow and preserved paged output. New native enrollments report their actual Linux/Windows/macOS family in existing metadata.

See [jobs and node runs](../operations/JOBS.md), [Flows](../operations/FLOWS.md), [CLI/MCP](../integrations/CLI_AND_MCP.md#execution-groups-and-multi-node-jobs) and [permissions](../operations/rbac.md).

Focused automated evidence includes real PostgreSQL/native authority with a synthetic gateway, protected reviewed-admission recovery, typed Flow bindings and actual responsive browser components. Installed native deployment acceptance remains **pending owner testing**. Follow the [five-node concurrency, failure-policy, low-disk Flow and mobile checklist](../operations/JOBS.md#owner-functional-acceptance); this campaign performs no production deployment.
