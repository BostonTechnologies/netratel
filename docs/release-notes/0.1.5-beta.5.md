# NetRatel 0.1.5-beta.5

Prepares [#729](https://github.com/BostonTechnologies/netratel/issues/729) for
RatelDesk's [durable automation deadlines and reconciliation](https://github.com/BostonTechnologies/rateldesk/issues/382).
The planned companion is **RatelDesk 0.1.3-beta.10**.

An authenticated execution receipt lets RatelDesk check the original admitted
request/run after a missed callback. It matches the saved service principal,
tenant, mapping revision, peer, parent request, task and attempt, and revalidates
current paired authority. Successful, failed and cancelled outcomes require
the existing terminal-readiness/result-hash proof. A confirmed provider timeout
is distinguished from an unconfirmed outcome; missing proof and unrecognized
states remain unknown.

Receipt reads use the existing paired read grant, return non-cacheable bounded
status information and never admit, dispatch, recover or replay work. Partial
records and unprotected legacy history remain unconfirmed without archival
writes or terminal-hash repair. Normal authenticated callbacks remain available.
See [execution reconciliation](../integrations/rateldesk-pairing.md#execution-reconciliation)
for the exact request headers and compatibility behavior.

An authorized identical ingest replay now commits recovery of its existing
request projection before returning the recovered acknowledgement. It retains
the recorded run and does not start another execution. A receipt GET does not
perform this recovery.

Upgrade NetRatel before the companion RatelDesk release. This NetRatel update
adds no database migration, pairing reset, credential or scope change. Preserve
the existing named connections, tenant mappings, credentials and persistent
keys, and follow the ordinary migration/startup procedure when upgrading from
older versions. RatelDesk applies its own upgrade migrations and retains both
SQLite and PostgreSQL support.

At source preparation, the focused managed-credential HTTP regressions passed
for exact receipts, terminal proof, unknown outcomes, read-only behavior,
revocation and persisted replay recovery. Required candidate PR/main CI,
the exact-tag hosted release build and publication, public archive/checksum/SBOM
verification, and anonymous digest pulls for all five image families remain
pending. The real paired native/browser and lost-callback/restart acceptance
also remains pending for this candidate. Build/distribution integrity and owner
production acceptance remain separate; a source checkout does not establish
installable release availability. Follow [release engineering](../deployment/RELEASES.md).
