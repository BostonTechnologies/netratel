# NetRatel 0.1.3-beta.2

This beta improves task-history inspection and script editing, and includes the
instance policy administration and operations layout fixes already merged for
this version.

## Task history

- Expand a run in place for target, tenant, timing, status, exit code and request
  details. The far-right link still opens the complete task/output view.
- Inspect a compact, scrolling console preview without leaving the list. Details
  load only when expanded. The preview is limited to 60 lines and 12,288
  characters; larger results link to Full output.
- Loading, empty output, running tasks and failed reads have explicit states.
  Refresh the preview when needed; live logs remain in the full task view.

Tracked in [#449](https://github.com/BostonTechnologies/netratel/issues/449).

## Script Library

- Compact single-line tree names, restored nested indentation and folder counts
  including matching scripts in subfolders.
- Delete moves beside Save above Monaco. Click the script name to rename it in
  place; Save persists name and content together using the existing revision
  checks.
- A full-screen dialog provides the same Monaco editor and rename, Save and
  Delete controls. Unsaved edits survive moving between the normal and
  full-screen views, and failed saves retain the draft.

Tracked in [#450](https://github.com/BostonTechnologies/netratel/issues/450).
See the [operator guide](../operations/README.md) for the workflow.

## Other fixes included in this beta

[PR #448](https://github.com/BostonTechnologies/netratel/pull/448) allows current
interactive instance administrators to manage operator policies without an
existing delegated MCP parent policy. Scoped callers retain their bounds, and
policy changes retain exact confirmations, idempotency and immutable audits.
It also compacts Jobs actions and Investigations layout, and presents expanded
Monitoring alerts as full-width evidence cards with validated ticket links.

The Windows desktop proof of concept remains disabled by default, as delivered
in beta.1. Client telemetry, terminal and ordinary execution continue through
their existing paths.

## Installation and focused acceptance

Use the completed release's matching archives, `SHA256SUMS`, `publication.json`
and digest-pinned Compose bundle. Follow [release installation](../../release/INSTALL.md)
and [self-hosting](../deployment/SELF_HOSTING.md). These UX changes add no database
migration.

After deployment, expand a completed and a failed run, inspect a large-output
run, and follow the retained full-output link. In Script Library, browse a nested
folder, rename a disposable script, edit its code in full screen, return with an
unsaved draft, then save and reload to confirm persistence. Confirm deletion of
the disposable script from the editor toolbar.

The existing hosted workflows validate source, build the native archives, and
publish the five images and downloadable assets. The publication record records
build/distribution integrity separately from owner deployment acceptance.
