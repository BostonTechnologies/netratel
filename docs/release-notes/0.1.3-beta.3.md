# NetRatel 0.1.3-beta.3

This beta adds tenant-scoped software inventory and estate intelligence from
[PR #453](https://github.com/BostonTechnologies/netratel/pull/453), implementing
[#452](https://github.com/BostonTechnologies/netratel/issues/452). It includes
the [beta.2 task-history, Script Library, policy administration and operations
improvements](0.1.3-beta.2.md) from
[PR #451](https://github.com/BostonTechnologies/netratel/pull/451) and
[PR #448](https://github.com/BostonTechnologies/netratel/pull/448).

## Software inventory

- Updated Windows and Linux native clients collect installed software on their
  first authenticated connection. Tenant scheduling defaults to enabled every
  seven days and is configurable beside Auto Update in tenant settings.
- Open **Software Inventory** from a client card for a full-screen snapshot,
  collection status and change history. Opening an inventory at least 30 minutes
  old requests a refresh when authorized; **Refresh inventory** requests one
  explicitly regardless of age. Offline requests remain queued.
- Use **Estate → Software Inventory** for searchable, sortable, server-paged
  installations, software prevalence with distinct device counts, estate change
  history and filtered CSV export.
- Windows collection reads uninstall registry metadata and available AppX/MSIX
  providers. Linux supports dpkg, rpm, pacman, snap and flatpak when installed.
  Collection never installs packages or reads license keys. macOS software
  inventory is unsupported in this beta.
- Durable, compressed, byte-bounded chunk uploads survive interruption and
  replay. Only a complete successful scan replaces the previous inventory and
  records additions, removals and version changes; partial or superseded scans
  preserve the last complete snapshot.

## API and MCP

The shared HTTP/stdio **netratel_software** tool and `SoftwareInventoryClient`
provide tenant policy, client status/snapshots, refresh, installations,
prevalence and change history. Reads do not initiate collection. Refresh and
policy changes require explicit confirmation and current delegated operation
authorization. Tenant isolation, application permissions and audit events apply
to inventory reads, exports and mutations.

See the [software inventory guide](../client/software-inventory.md) for supported
sources, freshness rules, permissions, limits and API/MCP examples.

## Upgrade and testing

Use this release's matching archives, `SHA256SUMS`, `publication.json` and
digest-pinned Compose bundle. Follow [release installation](../../release/INSTALL.md)
and [self-hosting](../deployment/SELF_HOSTING.md). Run the one-shot migrations
service before starting updated API replicas: `AddSoftwareInventory` adds
inventory tables and indexes. Update API, Web and MCP together, and update
Windows/Linux clients to collect inventory. Existing devices have no snapshot
until the updated client connects. Retain the migration when rolling application
binaries back; removing it deletes inventory and change history.

For owner acceptance, connect an updated Windows and Linux client, verify the
first scan, inspect client and estate views, test filtered export and explicitly
refresh inventory. Confirm partial scans preserve a previous complete snapshot,
offline collection resumes after reconnect, and tenant policy/access controls
behave as documented. Native Windows and distribution-specific package-manager
execution, deployment smoke and published-client runtime acceptance remain
owner-run checks. The Windows desktop proof of concept remains disabled by
default as in beta.1.

The generic hosted release workflows validate source, build native archives and
publish the five images and downloadable assets. `publication.json` records
build/distribution integrity separately from pending owner functional acceptance.
