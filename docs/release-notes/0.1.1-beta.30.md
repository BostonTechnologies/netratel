# 0.1.1-beta.30 — exact job mutation and run-action replay

Live testing of beta.29 reproduced successful job updates and parameter
additions whose exact confirmation replay returned `job_etag_mismatch`.
The original writes had succeeded once. [#333](https://github.com/BostonTechnologies/netratel/issues/333)
corrects reconciliation of those completed mutations.

All ten job-definition mutations now check for an authenticated recorded outcome
before validating the current definition version. An exact successful replay
returns the original job ID, resulting version and added parameter or step ID,
with `replayed: true`, including after later edits or soft deletion. It does not
repeat the mutation or create another mutation audit record. Unused plans stay
unconsumed until fresh-request validation succeeds.

Current caller, tenant, target, policy, ownership, plan binding and expiry still
apply. Fresh stale writes and changed confirmations remain rejected. Replays
of older receipts that stored only a job ID retain a compatibility fallback:
the current authorized ownership/tombstone version and no historical item ID.
Those older receipts cannot reconstruct fields they never stored.

The source review also identified
[#334](https://github.com/BostonTechnologies/netratel/issues/334): cancellation
replay was rejected after a run became terminal, and deletion replay was rejected
after the first deletion hid the run. The run-action repair applies the same
authenticated reconciliation before mutable state checks. New receipts preserve
the original run ID and action-result state; replay does not request another
cancellation or repeat the deletion/audit. Current cancellation gateway
requirements remain enforced. This additional finding came from source review,
separately from the beta.29 owner evidence.

The repair uses the existing confirmation and job-ownership storage, without a
new database migration. Existing endpoint/store tests cover the replay behavior
and denial controls. Required hosted validation, release builds and publication
use the existing generic workflows.
