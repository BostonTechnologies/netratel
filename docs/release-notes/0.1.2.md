# NetRatel 0.1.2

NetRatel 0.1.2 promotes the functionality delivered in 0.1.2-beta.5 to a stable
release. The stable promotion changes the product version and release
documentation; application behavior is unchanged from beta.5.

## AI Ops Chat and dashboard navigation

- **AI Ops → Chat** provides general conversations through the selected tenant's
  enabled Netclaw connection. Start with a question without selecting systems,
  an investigation title or investigation prompts.
- Chat includes separate saved history, title search, starter prompts, a
  multiline composer, formatted replies, copyable code and archive handling.
  Existing tool approvals, interrupted-request recovery and tenant permissions
  apply. Connection setup and global search open the appropriate tenant and
  conversation workspace.
- The landing dashboard has a compact tenant selector and consistent spacing
  between active alerts and recent jobs. **Online clients** and **Offline
  clients** open the directory with the selected tenant and presence filter.
- Alert-row actions use outlined buttons. Exact client links and legacy UUID
  search links resolve correctly, with directory filters retained in browser
  navigation.

See [Netclaw AI operations](../integrations/netclaw-ai-operations.md#general-chat)
and the [beta.5 release notes](0.1.2-beta.5.md).

## Integration credentials and policies

- HTTP MCP credential creation guides operators through **Connection → Server
  access → Tenant access → Policies → Review & create**. Server and tenant
  permissions have separate selectors, and the final review groups the
  connection, grants and base policies together.
- Credential creation and its approved policies commit atomically. A bounded
  encrypted handoff supports recovery of the one-time secret after a lost
  response.
- **Details → Configured access → Edit access** supports reviewed changes to an
  existing credential while retaining its identity, secret and exact expiry.
  Pending reviews can be reopened and reconciled; errors identify the failing
  stage and provide safe diagnostic references.
- Policy management groups active base policies with their client and operation
  exceptions. Named tenants and searchable selections replace identifier entry.
  Edit, disable, revoke, delete and explicit legacy consolidation retain the
  corresponding authorization checks and audit history.

See [HTTP MCP setup](../mcp-http/setup.md),
[policy management](../mcp-http/authentication.md#bounded-operator-policies-in-the-web-ui)
and the [beta.4 release notes](0.1.2-beta.4.md).

## Optional Windows computer use

An enrolled Windows Client can expose bounded observation and input for an
explicitly selected interactive application through the existing gateway and
Remote Support helper. Separate view and control permissions, reviewed target
policies, session ownership, confirmation, cancellation and manual takeover
govern the operations.

The feature is disabled by default on both API and Client. Providers include the
optional pinned Cua Driver and a limited native Windows fallback. Provider
capabilities are inspected at runtime; the optional sidecar is installed
separately. The existing owner-run Windows desktop acceptance procedure remains
documented in [Windows computer-use setup](../client/computer-use.md). See
[computer use through HTTP MCP](../mcp-http/computer-use.md) for permissions and
the operation flow.

## Installation and upgrade

Use the matching stable archives, `SHA256SUMS` and `publication.json` from the
[v0.1.2 release](https://github.com/BostonTechnologies/netratel/releases/tag/v0.1.2).
The completed Compose bundle pins the five published container images by digest.
Follow [release installation](../../release/INSTALL.md) and
[self-hosting](../deployment/SELF_HOSTING.md), retaining the existing
configuration and persistent state.

Upgrades from 0.1.1 include the computer-use session, integration-policy hierarchy
and integration-setup handoff migrations introduced during the 0.1.2 beta series.
Run the supplied migrations before starting the matching API and Web. The stable
promotion adds no migration beyond beta.5.

`Directory.Build.props` remains the sole product-version authority. The existing
generic workflows validate the source, build the platform archives and publish
the five container images with checksums, SBOMs and the publication record.
Distribution integrity and owner deployment acceptance are recorded separately
in that record.
