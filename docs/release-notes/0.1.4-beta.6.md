# NetRatel 0.1.4-beta.6

Chat and AI Ops keep the composer, Send button and conversation actions inside the available viewport. Long history lists and transcripts scroll independently. This follows the bounded workspace and fixed composer pattern used by RatelDesk. Enter sends; Shift+Enter adds a new line. Ctrl/Command+Enter remains supported, and IME composition does not submit. Input binding preserves rapid edits, and fullscreen keeps the latest reply in view when following output.

Archive confirmation opens in a dialog visible from the bottom of a long transcript, including fullscreen. Active and unresolved conversations still require acknowledgement of possible remote effects. Legacy unresolved records without an active message ID can now archive with that acknowledgement. Confirmation is fenced to the conversation and active turn; errors remain visible and can be retried.

Recovery results, last attempts and request failures stay outside transcript scrolling. A completed session check shows feedback even when it reuses a saved result. A provider rejection of a saved history name (`HTTP 400`, `input[n].name`) shows **History rejected** with archive/new-chat or daemon repair guidance. Reconnecting cannot rewrite native history; this release does not claim to repair it or replay past operations. See the [Netclaw guide](../integrations/netclaw-ai-operations.md).

Focused browser acceptance uses synthetic Chat and AI Ops fixtures with full history, long transcripts, normal and fullscreen viewports, keyboard sending, recovery and archive failure/retry. PostgreSQL regressions cover legacy archive acknowledgement and current-turn/session-bound provider diagnostics beyond the transcript page. These checks do not replace owner testing against the deployed NetClaw daemon. Release publication records distinguish distribution integrity from pending owner functional acceptance.
