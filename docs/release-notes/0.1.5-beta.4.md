# NetRatel 0.1.5-beta.4

Repairs [#727](https://github.com/BostonTechnologies/netratel/issues/727) with
[RatelDesk #378](https://github.com/BostonTechnologies/rateldesk/issues/378).

Paired catalogue projections, tenant-scoped target choices, command authoring
and input sync support canonical job targets using the existing read/invoke
grants. Declared runtime inputs and offline workers do not hide valid job
definitions. Contract negotiation preserves older fixed-agent consumers.

Managed ingress persists one aggregate parent and frozen plan with the exact
saved connection and request-task attempt before dispatch. Canonical HA selection,
node membership, execution environment, concurrency, failure policy and deadlines
remain enforced. Authority and target drift are checked at dispatch/continuation.
Retries observe the same parent; changed payloads conflict and later attempts
require terminal predecessor evidence. Final callback/outbox projection uses the
aggregate result hash and includes bounded child results. Unknown stays explicit.

The automatic migration makes the binding's fixed agent optional and adds the
frozen target-plan digest, retaining legacy bindings and historical evidence.
Upgrade this provider before RatelDesk 0.1.3-beta.9 and retain existing named
connections, credentials and keys. See [the pairing guide](../integrations/rateldesk-pairing.md#target-aware-self-service-automation)
for compatibility and the owner redeployment/retest procedure.

Focused PostgreSQL tests use issued paired credentials and real aggregate/actor
admission with isolated synthetic gateways. The opt-in source-pair lane exercises
the real native Client for legacy, explicit-node and HA jobs authored through
RatelDesk. Their receipts, required PR/main CI, hosted builds and public
artifact/image verification remain distinct from owner production acceptance.
