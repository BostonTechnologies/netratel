# 0.1.3-beta.4 — compact installers workspace and reliable software inventory

## Agent Installers & Updates

The `/clients/mgmt` workspace puts the main tabs immediately below a compact
header. The tenant selector is width-constrained, and rollout eligibility and
release automation details are collapsed by default. Important eligibility or
automation attention indicators remain visible without expanding the details.

**Local imports** is a separate top-level tab with a shortcut from the GitHub
catalogue. It contains downloaded release packs, source checks, approval and
retry/cancel actions, confirmed local deletion and cleanup status. These records
remain available independently of GitHub discovery. Deletion blockers, operator
confirmation, historical receipts and automatic re-import suppression are
unchanged.

GitHub releases, Local imports, Packages, Auto-updates, Activity and Suspended
provide **20 / 50 / 100** rows per page, defaulting to 20. Catalogue page-size
changes return to page one. The GitHub view composes bounded cached API pages;
50-row views preserve entries across the underlying 20-row boundaries. Upstream
availability and scan-limit messages are retained rather than inventing a total.
Existing live activity, automation draft protection and tenant rollout rules are
preserved.

## Software inventory reliability and estate UX

Includes the software inventory fixes merged before this release source change:
collection timestamps are compared at PostgreSQL precision so multi-chunk
uploads do not become stuck after the first accepted chunk. Existing queued
payloads and duplicate acknowledgement hashes remain compatible.

Saved inventory loads independently of a live refresh request. The reusable
full-screen client view shows receiving progress and recoverable timeout/error
states while retaining the last complete snapshot. Estate overview cards and
Software, Installations, Devices and Changes views expose coverage and
never-scanned devices. Friendly names and reported hostnames replace GUIDs as
primary client labels, including existing API/MCP query responses.

See the [software inventory guide](../client/software-inventory.md) for the
collection contract, permissions and troubleshooting.

## Owner checks after deployment

Open Agent Installers & Updates and verify the tabs and first data rows are near
the top of the desktop viewport. Expand tenant eligibility and automation details
and confirm the existing policy information remains accessible. Open Local
imports directly, change rows per page, and check that switching tabs preserves
the selected channel and page-size choices.

On Windows and Linux clients, confirm first collection completes, existing
inventory appears while a refresh runs, and the estate page displays client
names. Test with an inventory larger than 100 packages to exercise multiple
upload chunks.

Source compilation and automated regression evidence belong to the linked CI
run. Native client and deployed visual acceptance are owner-run checks; this note
does not assert that those checks or release publication have occurred. Published
assets and the distribution publication record establish distribution status.
