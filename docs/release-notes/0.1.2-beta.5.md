# NetRatel 0.1.2-beta.5

This beta adds a dedicated Netclaw chat workspace and improves the landing
dashboard's layout and client navigation.

## AI Ops Chat

- **AI Ops → Chat** opens a tenant-scoped conversation using the tenant's existing
  enabled Netclaw connection. Send the first question without choosing systems,
  a title or investigation prompts.
- A responsive workspace provides separate chat history, title search, starter
  prompts, a multiline composer, formatted assistant replies and copyable code.
- Saved transcripts, live output, tool decisions, interrupted-request recovery
  and archive handling reuse the existing durable Netclaw conversation pipeline.
- General chat attaches tenant scope and platform instructions, without selected
  system observations, alert context or investigation prompt snapshots. Actual
  tool calls continue to use the configured Netclaw and NetRatel permissions.
- Connection setup links preserve the tenant. Global search distinguishes chats
  from investigations and opens each in the correct workspace.

See [Netclaw AI operations](../integrations/netclaw-ai-operations.md#general-chat)
for the operator workflow and permissions.

## Dashboard and clients

- The active-alert and recent-job sections have a consistent 20px gap, and the
  dashboard tenant selector is compact and left aligned.
- **Online clients** and **Offline clients** link to the client directory with
  the selected tenant and corresponding presence filter applied.
- Alert-row **Alerts** and **Client** actions use outlined buttons with icons.
- Client links carry an exact tenant and client filter. Legacy UUID search links
  also resolve, and directory filters remain represented in browser navigation.

## Installation and validation

Use the matching archives, `SHA256SUMS` and `publication.json` from the completed
[beta release](https://github.com/BostonTechnologies/netratel/releases/tag/v0.1.2-beta.5).
The Compose archive pins the five published container images by digest. Follow
[release installation](../../release/INSTALL.md) and
[self-hosting](../deployment/SELF_HOSTING.md) for an existing installation.

This update adds no database migration. General chats and investigations share
the existing conversation storage while retaining separate history lists. The
source includes focused payload, persistence, authorization, navigation and
component regressions. The publication record identifies completed distribution
verification separately from owner deployment acceptance.
