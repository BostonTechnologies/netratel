# NetRatel 0.1.1-beta.14

Repairs [issue #239](https://github.com/BostonTechnologies/netratel/issues/239): job lifecycle delivery, task target presentation, effective execution settings, truthful outcome projections, and compact live Jobs/Tasks workspaces.

- Server dispatch time and agent event time are separate clocks. Authenticated lifecycle versions and sequences establish order; server receipt times establish projection observation times. An agent clock behind the API, or a backward wall-clock correction, no longer rejects otherwise valid evidence. The production clock offset and first rejected production transition have not been measured.
- Job receipt acknowledgements follow durable authority commits. A transport reconnect replays the same pending receipt and retains its executor; it does not restart the command. Receipt memory survives transport reconnect within the presence session. Recovery retains the original reconciliation deadline: after an unknown outcome closes the run, exact committed retries remain idempotent, while new late evidence cannot rewrite the terminal outcome. A process/presence restart loses that client memory; historical uncertain execution remains unknown and is not automatically replayed.
- Start evidence follows actual process creation. Missing scripts/interpreters and dispatch failures keep start and exit evidence absent. Unknown physical outcomes, skipped later steps, confirmed failures, cancellation, and actual native timeouts have distinct states.
- Request-ID, numeric detail, recent/history, and job presentation use tenant-scoped targets and captured execution labels. Stored names describe execution context, not live client presence. Historical missing environment/start/exit values remain unknown.
- Run policy and environment round-trip and are frozen for execution. Copied jobs preserve configuration; an unfinished new job cannot activate its schedule before final Save.
- Committed task/run/output changes drive authorized SSE invalidations and snapshots. Reconnection and periodic snapshots recover missed notifications. Output is ordered, deduplicated, bounded, and reports truncation; tabs and expanded steps remain stable.
