# 0.1.4-beta.1 — shared conversations and script placement

Chat and Investigations share one interactive conversation surface with
Maximise/Restore controls beside Archive, keyboard Escape and retained drafts,
transcripts and detail expansion. Compact tool rows expose name, recorded status
and UTC time. Selected, bounded and server-redacted arguments, results, failure
codes and optional trace metadata survive refresh. Browser display preferences
apply to both routes; approvals, recovery and errors remain visible. Existing
events cannot recover details that were never stored.

Recovery restores and deduplicates available history excerpts without resending
messages or tool approvals. New turns retain pre-send native turn counts for
terminal reconciliation. Historical count evidence does not assert business
success or release an automated Flow as successful. **Older conversations lack
that baseline, and the supported daemon history contract cannot prove their
per-message terminal outcome.** These remain explicitly unconfirmed, with a last
attempt time and review/archive/new-conversation guidance. See the
[AI operations guide](../integrations/netclaw-ai-operations.md#recovery-and-approvals).

Script Library adds a Move script folder control in both editor layouts. Its
dedicated dialog selects root, an existing folder or a new nested path while
retaining unsaved name/content. The production MCP create/update contract also
supports `folderPath`; moves bind the observed source revision and ETag to the
confirmed destination, retain identity/content/parameters and return placement.

The navigation Release Info popover shows a short commit and actual UTC build
metadata for Web and API, with explicit unavailable values for older builds.

The compact Agent Installers workspace, first-class Local imports and 20/50/100
pagination from issue #457 already shipped in 0.1.3 through PR #460. This release
retains that implementation; the older conflicting PR #458 is superseded.

Run the matching one-shot migrations service before replacing API replicas.
Use the release's checksums, SBOMs, publication record and digest-pinned Compose
bundle. Hosted build/distribution verification and owner deployment acceptance
are distinct. Live custom-daemon recovery, tenant tool approvals and native
deployment testing remain owner acceptance; these notes do not assert they ran.
