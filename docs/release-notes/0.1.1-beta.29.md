# 0.1.1-beta.29 candidate — managed automation retry attempts

Managed orchestration ingest retains separate durable bindings for each caller
execution attempt. Exact replay returns the original run. A distinct attempt
is admitted only after the preceding run is reconciled terminal, with serialized
admission preventing concurrent retries from starting two runs. Prior bindings
remain available for callback isolation; unknown or active predecessors remain
conflicts. The migration refuses a downgrade that cannot retain attempt history.

The paired catalog now projects a current job's server-owned AgentId into its
required client identity. Jobs created through current job CRUD can therefore
be selected and bound by the companion without relying on a populated legacy
identity. Tenant and active-agent checks still apply.

Use with the companion RatelDesk persisted-attempt repair. Required hosted CI,
reviewed merge, immutable publication and fresh deployed callback/campaign
verification remain separate gates. These notes claim no unexecuted acceptance
or publication result and do not change the stable channel.
