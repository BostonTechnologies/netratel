# NetRatel 0.1.3 — software inventory and clearer operations

## Software inventory

Windows and Linux agents collect installed software on their first authenticated
connection and on a configurable tenant schedule, enabled every seven days by
default. Client cards open a full-screen inventory with saved installations,
change history, scan progress and an authorized refresh action. Saved rows remain
available while collection runs; incomplete scans preserve the previous complete
snapshot. Durable chunk delivery and PostgreSQL timestamp handling support
multi-chunk inventories and safe replay after interruption.

The estate workspace adds software/version prevalence, installation search and
filters, device coverage including never-scanned clients, change history and
filtered CSV exports. Friendly client names and hostnames identify devices.
Windows registry and AppX/MSIX, plus available Linux dpkg, rpm, pacman, snap and
flatpak sources, are supported. macOS software collection remains unsupported.
The shared HTTP/stdio `netratel_software` tool exposes inventory reads, refresh
and tenant policy operations under existing permissions and confirmation rules.

Package details now span the full table width in both the client dialog and
estate installations view, using the Monitoring alert-card treatment. Grouped
cards show package identity, installation, client/platform and collection timing.
The keyboard-accessible disclosure includes focus styling, responsive cards,
wrapping for long identifiers and reduced-motion support. Missing metadata is
explicitly labelled; detection and last complete scan times remain distinct.

See the [software inventory guide](../client/software-inventory.md) for sources,
scheduling, freshness, API/MCP operations and permissions.

## Operations and management

- Agent Installers & Updates has a compact header, accessible top-level tabs,
  collapsed eligibility/automation details and a separate Local imports view.
  Inventory and release actions retain their existing authorization and receipts.
  Installer lists offer 20 / 50 / 100 rows, with bounded GitHub catalogue paging.
- Task History expands runs in place with target, timing, status and a bounded
  output preview, retaining links to complete output.
- Script Library offers compact nested navigation, in-place rename and a
  full-screen editor that retains unsaved changes. Save and Delete sit together
  above the editor and preserve revision checks.
- Monitoring alerts use full-width evidence cards and validated incident links.
  Interactive instance administrators can manage operator policies without an
  existing delegated MCP parent policy; scoped callers retain their bounds.

The Windows desktop proof of concept remains disabled by default.

## Upgrade and acceptance

Use this release's matching archives, `SHA256SUMS`, `publication.json` and
digest-pinned Compose bundle. Follow [release installation](../../release/INSTALL.md)
and [self-hosting](../deployment/SELF_HOSTING.md). When upgrading from a version
before software inventory, run the one-shot migrations service before API
replicas, then update Windows/Linux clients so they can collect inventory. This
release's detail-panel changes add no schema migration.

After deployment, expand package details from a client card and from the estate
installations view. Check long package identifiers/paths, missing install metadata,
narrow screens and keyboard operation. Confirm saved inventory remains visible
during refresh and client names, filters and exports still behave as expected.

Hosted CI and release workflows establish source, build and distribution integrity.
The publication record reports that separately from owner deployment and native
runtime functional acceptance; this note does not claim those checks have run.
